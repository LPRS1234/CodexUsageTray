# Codex Usage Tray

Windows 시계 옆 알림 영역(시스템 트레이)에 Codex의 남은 사용량 비율을 숫자 아이콘으로 표시하는 로컬 앱입니다.

## 실행

### 다른 PC에 설치

`bin\setup\CodexUsageTray-Setup.exe` 하나를 다른 Windows PC로 복사하여 실행합니다.
Windows 10/11과 .NET Framework 4.8 이상이 필요합니다. 설치는 현재 사용자 계정에만 적용되며 관리자 권한이 필요하지 않습니다.

- 설치 화면에서 `Windows 로그인 시 자동 실행`을 선택할 수 있습니다. 처음 설치할 때는 선택하지 않은 상태입니다.
- 시작 메뉴의 `Codex Usage Tray`에서 앱을 실행하거나 제거할 수 있습니다. Windows의 설치된 앱 목록에서도 제거할 수 있습니다.
- 설치 후에도 앱 메뉴에서 자동 실행을 켜거나 끌 수 있습니다.
- 다른 PC에도 Windows용 Codex CLI를 설치하고 ChatGPT 계정으로 로그인해야 사용량을 표시합니다. [공식 Codex CLI 안내](https://developers.openai.com/codex/cli/)를 참고하세요. 로그인 정보는 설치 파일에 포함되지 않습니다.
- 설치 위치는 `%LOCALAPPDATA%\Programs\CodexUsageTray`입니다. 재설치나 업데이트 전에 실행 중인 앱을 종료해야 합니다.
- 제거할 때 앱의 자동 실행 등록과 설치 파일을 삭제하며 카드 위치·표시 방식·테마 설정과 Codex 로그인 정보는 유지합니다.

### 자동 업데이트

Setup으로 설치한 앱은 시작 30초 후와 이후 6시간마다 [GitHub 정식 릴리스](https://github.com/LPRS1234/CodexUsageTray/releases/latest)를 확인합니다.
새 버전의 설치 파일을 내려받아 GitHub가 제공하는 SHA-256과 파일 버전을 검증한 후 앱을 종료하고 업데이트합니다. 완료되면 앱을 다시 실행하며 자동 시작 설정과 앱 설정은 유지됩니다.

`업데이트 확인` 메뉴로 바로 확인할 수도 있습니다. 미리보기·초안·이전 버전은 설치하지 않습니다. 인터넷 연결 또는 검증 실패 시 현재 버전을 계속 사용하고 다음 주기에 다시 확인합니다.
개발 폴더에서 `run.cmd`로 실행한 앱은 자동 업데이트하지 않습니다. 업데이트 확인 시 GitHub에 연결하며 계정·사용량·인증 정보는 보내지 않습니다.

`run.cmd`를 더블 클릭합니다. 이미 빌드된 실행 파일은 `bin\CodexUsageTray.exe`입니다.

시계 옆 숫자 아이콘을 왼쪽 클릭하면 Windows 스타일의 사용량 팝업 패널이 열립니다. 오른쪽 클릭하거나 패널의 설정 버튼을 누르면 옵션 메뉴가 열립니다.

- `대시보드로 이동`을 눌러 누적 토큰, 일별 토큰 사용량, 남은 사용량과 계정 정보를 브라우저에서 확인
- 제한 주기별 남은 사용량과 초기화 시각 확인
- 즉시 새로고침
- 숫자 아이콘에 표시할 기간을 5시간 또는 7일로 선택
- 패널에서 두 기간의 남은 비율과 초기화 시각을 함께 확인
- Windows 로그인 시 자동 실행 설정 또는 해제
- 정보 화면에서 표시 기준, 갱신 주기, 자동 실행 상태 및 개인정보 처리 확인
- 앱 종료

## 표시 방식

- Windows의 표준 알림 영역 API로 시계 옆에 숫자 아이콘 한 개를 등록합니다. 아이콘의 위치와 숨김 여부는 Windows가 관리합니다.
- 별도의 작업표시줄 앱 버튼은 표시하지 않습니다.
- 숫자는 선택한 기간의 남은 비율(%)이며, 기본값은 5시간입니다. 예를 들어 `78`은 78%가 남았다는 뜻입니다.
- 이전에 두 기간을 함께 표시하도록 설정했다면 5시간 숫자로 전환합니다. 7일 선택은 유지합니다.
- 마우스를 올리면 두 기간의 남은 비율과 갱신 상태를 확인할 수 있습니다.
- 클릭 패널은 5시간과 7일의 읽기 전용 진행선, 초기화 시각, 새로고침·대시보드·자동 실행 버튼을 제공합니다.
- 패널은 아이콘이 있는 모니터의 작업 영역 안에 배치되며, 바깥 클릭이나 Esc 키로 닫을 수 있습니다. 패널을 닫아도 앱은 계속 실행되며, 옵션 메뉴의 `종료`로 앱을 종료합니다.
- 갱신 실패 시 마지막 값과 경고 표시를 유지하며, 마지막 성공 시각과 실패 상태를 패널에서 확인할 수 있습니다.
- Windows 설정에 따라 아이콘이 숨겨진 아이콘 목록에 들어갈 수 있습니다. 항상 표시하려면 작업표시줄 설정에서 표시를 켜거나 트레이로 이동하세요.

같은 기간의 제한이 여러 개면 남은 비율이 가장 낮은 값을 표시합니다. 사용량 변경 알림을 받으면 즉시 갱신하며, 누락에 대비해 10초마다 다시 확인합니다.

대시보드 화면도 10초마다 현재 상태를 확인합니다. 계정 정보와 누적·일별 토큰 통계는 60초마다 갱신하며, 대시보드를 열거나 `지금 갱신`을 누르면 즉시 다시 조회합니다.

## 개인정보 및 인증

별도 API 키를 입력하지 않습니다. 설치된 Codex CLI의 App Server를 로컬 `stdio` 연결로 실행하고, 기존 Codex 로그인 상태를 이용해 사용률, 초기화 시각, 토큰 활동 통계와 계정 이메일·요금제를 조회합니다. 인증 토큰을 직접 읽거나 저장하지 않으며 계정·사용량·인증 정보를 외부로 보내지 않습니다. 앱 업데이트 확인과 설치 파일 다운로드에는 GitHub 연결을 사용합니다.

대시보드는 앱 안에서 시작한 `127.0.0.1` 전용 서버로 제공됩니다. 앱이 종료되면 대시보드 연결도 함께 종료됩니다. 계정 종류에 따라 일부 토큰 통계가 제공되지 않을 수 있습니다.

## 다시 빌드

`build.cmd`를 실행합니다. Windows에 기본 포함된 .NET Framework 4.8 C# 컴파일러를 사용하므로 별도 개발 도구 설치가 필요하지 않습니다.

`package.cmd`를 실행하면 현재 소스로 앱과 단일 Setup 파일을 다시 만듭니다. 실행 중인 개발 앱을 건드리지 않도록 `bin\setup\payload`에서 배포용 앱을 빌드합니다.
별도 빌드 출력 폴더가 필요하면 `build.cmd <출력 폴더>`를 사용할 수 있습니다.

### 새 버전 재배포

1. 변경 후 `src\Program.cs`의 `AssemblyVersion`과 `AssemblyFileVersion`을 같은 새 버전으로 올립니다. 예: `1.7.1.0`.
2. `package.cmd`와 `test.cmd`로 빌드와 검증을 진행합니다.
3. 관련 소스를 검토하여 커밋·푸시하고 새 버전의 릴리스 설명 파일을 작성합니다.
4. GitHub CLI 로그인 후 `powershell -NoProfile -File .\publish-release.ps1 -NotesFile .\release-notes.md`를 실행합니다.

배포 스크립트는 스크립트 실행이 허용된 PowerShell 환경에서 사용합니다. 실행 정책으로 차단되는 환경에서는 GitHub 웹의 릴리스 화면에서 수동으로 배포할 수 있습니다.

배포 스크립트는 원격 저장소와 소스의 커밋·푸시 상태를 확인하고 다시 검증합니다. 설치 파일과 체크섬을 GitHub 초안 릴리스에 업로드한 뒤 GitHub의 파일 해시까지 확인하여 정식 릴리스로 공개합니다.
기존 릴리스를 강제로 덮어쓰지 않습니다. 새 정식 릴리스가 공개되면 이미 설치된 앱이 다음 확인 때 자동으로 업데이트됩니다.
수동 배포 시에도 `v1.7.1`처럼 버전 태그를 사용하고 `CodexUsageTray-Setup.exe`라는 이름으로 파일을 첨부해야 합니다.
Setup에는 코드 서명을 적용하지 않았으므로 Windows가 게시자를 확인할 수 없다는 안내를 표시하거나 앱 제어 정책에 따라 실행을 차단할 수 있습니다.

## 코드 구조

- `src/App`: 트레이 앱 흐름, 사용량 갱신, 설정과 자동 실행 관리
- `src/Codex`: Codex App Server 통신과 응답 모델
- `src/Dashboard`: 로컬 대시보드 HTTP 서버와 화면 상태
- `src/UI`: 시스템 트레이 숫자 아이콘, 사용량 패널과 옵션 메뉴
- `src/Interop`: Windows API 연결 코드
- `installer`: 사용자별 Setup 화면, 파일 교체·복구, 시작 메뉴·자동 실행·제거 등록
- `assets/dashboard.html`, `dashboard.css`, `dashboard.js`: 대시보드 구조, 스타일, 동작
- `tests`: 로컬 대시보드 서버 스모크 테스트

`test.cmd`를 실행하면 대시보드의 정적 파일·API 경로, 실제 Codex 사용량 갱신 연결, 업데이트 파일 검증, 임시 경로에서 설치·업데이트·제거와 실패 시 복구를 검사합니다. 설치기 테스트는 고유한 임시 폴더와 테스트용 레지스트리만 사용합니다. 테스트는 계정명이나 사용량 수치를 출력하지 않습니다.

Codex CLI가 업데이트되어 설치 경로가 달라진 경우 앱을 다시 시작하세요.
